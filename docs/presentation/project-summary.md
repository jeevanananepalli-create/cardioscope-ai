# CardioScope AI — project summary

*Cardiovascular Risk Visualization & Prediction. A research and education prototype; not a medical device.*

Six sections, each sized for one page.

---

## Page 1 — Problem and solution

**Problem.** Coronary artery disease is confirmed by angiography, an invasive procedure. Routine
measurements (history, examination, ECG, blood tests, echocardiography) are available first. Two
questions follow: how much do those measurements say about what angiography will find, and how can
a model's answer be shown without being mistaken for a finding?

**Solution.** CardioScope AI is a web application that:

1. predicts CAD and stenosis of the LAD, LCX and RCA from 52 entered measurements;
2. explains each prediction with SHAP feature attribution;
3. shows the three vessel predictions on an interactive 3D heart built from open anatomical data;
4. lets the user explore how the models respond when inputs change;
5. shows how well each model actually performs, including where it performs poorly.

**What it is not.** It does not diagnose, it does not locate lesions, and it has not been validated
outside one 303-patient dataset. Every screen says so.

## Page 2 — System architecture

```
Browser: Next.js dashboard  ──HTTP/JSON──►  FastAPI service  ──loads──►  four saved pipelines
 form · 3D view · SHAP · what-if · metrics     strict schema                (preprocess + model)
                                                                                  ▲
                                             ML pipeline: validate → CV → select → calibrate → evaluate
```

- **One feature schema** drives training, the API's request validation and the dashboard's form.
- **Each saved model contains its own preprocessing**, so inference cannot diverge from training.
- **Every displayed number has one source**: the evaluation pipeline's output, served by the API.
- **Failure is handled explicitly**: unreachable backend, missing models, invalid input, malformed
  responses, failed explanations and failed 3D assets each have a defined, tested behaviour.

Technology: Python, pandas, scikit-learn, XGBoost, SHAP; FastAPI and Pydantic; Next.js, React,
TypeScript, React Three Fiber.

## Page 3 — ML pipeline and leakage prevention

**Data.** UCI extension of the Z-Alizadeh Sani dataset: 303 patients, 54 usable inputs, four
angiography outcomes. No missing values.

**Leakage prevention.** The four outcome columns (`LAD`, `LCX`, `RCA`, `Cath`) can never be inputs:

- a hard-coded blacklist that configuration cannot change;
- a whitelist of inputs, and refusal to build a schema containing a blacklisted column;
- checks at feature-matrix build, fit, cross-validation, transform, artifact save/load and the API;
- dedicated tests that fail if a guard is removed (verified by removing one).

**Method.**

1. One patient-level 80/20 split shared by all four models; the 20% is used once, at the end.
2. Repeated stratified 5×5 cross-validation of 22 candidates per target (logistic regression, SVM,
   random forest, XGBoost; small grids; with and without class weighting). Preprocessing is fitted
   inside each fold.
3. A selection rule fixed in advance: within 0.01 ROC-AUC of the best, then within 0.005 Brier
   score, then the simplest algorithm.
4. Calibration and threshold tuning judged by nested cross-validation and adopted only beyond two
   corrected standard errors.

## Page 4 — 3D visualization and explainability

**3D view.** Real reference anatomy from BodyParts3D (heart, coronary arteries with branches,
arterial tree, veins, body outline) and Z-Anatomy (nervous system, skeleton, organs), simplified
for the browser. Rotate, zoom, pan, heart-focus and torso-context modes, optional layers.

- LAD, LCX and RCA are coloured by their model's predicted probability through four configurable
  display bands. Nothing else is ever coloured by a model.
- The anatomy is generic, not the patient's; colour is model output, not imaging.
- Selecting a vessel shows its probability, predicted class, band, top contributors and their values.

**Explainability.** SHAP per model (tree and linear explainers), reported per original input.
Global importance, per-patient contributions and per-vessel explanations are all available.
Wording is deliberately non-causal: "contributes toward a higher predicted LAD risk".

**What-if.** "Exploratory model simulation": change inputs within the training range, see before
and after for all four outputs, and the 3D view updates. It shows model sensitivity, not the effect
of an intervention.

## Page 6 — Limitations, future work, implementation

**Limitations.**

- One small, single-centre dataset; everyone in it was referred for angiography; no external validation.
- Two of four models are weak; probabilities are only approximately calibrated.
- Inputs describe the whole patient; none measures a specific artery. The models learn association only.
- The anatomy is generic; two anatomy sources are aligned to within a few millimetres; nerves are
  drawn thicker than life.
- Units, labels and input limits were not clinically reviewed.

**Future work.**

- External and prospective validation; subgroup and fairness analysis.
- Larger and multi-centre data; richer inputs (for example ECG signals rather than summaries).
- Uncertainty shown per prediction, not only per model.
- Clinical review of wording, units and limits; usability testing.

**Implementation.**

- Automated tests at four levels: ML, API, dashboard components, and end to end in a real browser
  against the real models.
- Reproducible: fixed seeds, pinned versions, one command to train and one to evaluate.
- Runs in a browser without a dedicated GPU: on-demand rendering, capped pixel ratio, optional
  layers fetched only when switched on.
- No patient data stored or logged; no secrets required.
